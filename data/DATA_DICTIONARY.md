# GlowPath Synthetic Dataset — Data Dictionary

Generated by `generate_dataset.py`, seed=42, fully reproducible. Scale: 10,000 users,
300 products, 5-dimensional hidden latent space.

## Why synthetic data with a controlled ground truth

There is no real skincare interaction dataset at this scale — user-level funnel
events (view/click/cart/purchase) *and* a 30-42 day self-reported skin outcome —
that is publicly obtainable or licensable for a portfolio project. Even if one
existed, it would give no way to check whether a from-scratch matrix
factorization actually recovered the right latent structure, only whether its
loss went down on held-out interactions. Loss decreasing is consistent with
overfitting noise; it is not proof the model found real behavioral factors.

By generating the data from known hidden user and product latent vectors, and
holding those vectors out in separate "answer key" files, we can later validate
MF quantitatively: align the learned embeddings to the true ones (e.g. via
correlation of pairwise similarities, or Procrustes rotation) and check whether
the model actually reconstructed the generating structure. That is a much
stronger correctness check than loss curves alone, and it's the reason the
ground-truth latents are generated at all and why they are never merged into
the user-facing files.

## Files

### `glowpath_users.csv`
One row per user. No latent information — this is what the recommender is
allowed to see.

| Column | Type | Description |
|---|---|---|
| `user_id` | int | 1..10,000 |
| `skin_type` | categorical | oily / dry / combination / sensitive / normal, drawn uniformly |
| `primary_concern` | categorical | one of acne/pigmentation/aging/dullness/dehydration/sensitivity |
| `secondary_concern` | categorical | same concern universe, **guaranteed different from `primary_concern`** (sampled as an offset of 1-5 positions from primary, mod 6) |
| `signup_date` | date | uniformly sampled up to 2 years back from the dataset snapshot date (2026-07-06) |

### `glowpath_ground_truth_user_latents.csv` — ANSWER KEY, do not merge into features
| Column | Type | Description |
|---|---|---|
| `user_id` | int | joins to `glowpath_users.csv` |
| `latent_0`..`latent_4` | float | hidden 5-dim taste vector, `N(0,1)` iid per dimension |

### `glowpath_products.csv`
One row per product.

| Column | Type | Description |
|---|---|---|
| `product_id` | int | 1..300 |
| `category` | categorical | cleanser/serum/moisturizer/sunscreen/toner/mask/eye_cream |
| `price_tier` | categorical | budget/mid/premium |
| `key_actives` | comma-separated string | 1-2 active ingredients from the list below |
| `concern_tags` | comma-separated string | 1-2 concerns this product targets (same 6-concern universe as users) |
| `irritation_risk` | float | max irritation weight across the product's `key_actives` |

### `glowpath_interactions.csv`
Clickstream-style event log: **one row per funnel stage actually reached**, not
one row per exposure. If a user viewed a product and clicked but didn't cart,
that exposure produces 2 rows (`view`, `click`); a full funnel-through-purchase
produces 4 rows (`view`, `click`, `cart`, `purchase`).

| Column | Type | Description |
|---|---|---|
| `interaction_id` | int | unique row id |
| `user_id` | int | joins to users |
| `product_id` | int | joins to products |
| `event_type` | categorical | view / click / cart / purchase |
| `timestamp` | datetime | when this stage occurred |
| `affinity_score` | float | the underlying affinity draw for this exposure (see below). **Diagnostic only** — a real production system would not have this feature at serve time, since it's derived directly from the hidden latents. Included here purely so later analysis/debugging of the funnel and reward simulation has something to check against; do not feed it into the recommender or bandit as an input feature. |
| `long_horizon_signal` | float, [0,1] | only populated on `purchase` rows: self-reported skin outcome 30-42 days later. Higher = better. |
| `long_horizon_observed_date` | date | only populated on `purchase` rows: `timestamp` + 30-42 days |
| `days_since_last_purchase_at_time` | int | days since this user's most recent **prior** purchase, as of this row's timestamp; **-1 means no prior purchase yet** (new user or first exposure in the observed history). Intended as a bandit context feature. |

#### Exposure generation (sparsity)

Each user is exposed to a Poisson(18)-distributed number of products (not a
full cross join — real recsys matrices are sparse). Products are sampled
without replacement per user. This yields ~94% sparsity in the
(user, product) exposure matrix at this scale, matching the target.

#### Affinity model

For each (user, product) exposure:

```
affinity = dot(user_latent, product_latent) / sqrt(5)
         + 0.8   if user's {primary, secondary} concern overlaps product's concern_tags, else 0
         + N(0, 0.3) noise
```

#### Funnel model (view -> click -> cart -> purchase)

Each stage's pass probability is `sigmoid(slope * affinity + bias)`, with the
slope steepening at each successive stage (1.2 -> 1.8 -> 2.4) so later stages
discriminate more sharply on affinity — converting further takes a stronger
signal, not just clearing the same bar again. The bias at each stage is
solved numerically (bisection) against the *actual realized* affinity
distribution of exposures that reached that stage, so the target rates below
are hit empirically in the generated data, not just approximately in
expectation:

- **view -> click**: target ~10-15% (spec'd assumption: these are curated/
  relevant exposures the recommender chose to show, not random browsing, so a
  higher-than-generic-ecommerce click-through rate is a defensible choice)
- **click -> cart**: target ~35% — **this rate is not specified by the product
  spec; it's an assumption we made explicitly** to have a defined mid-funnel
  stage, chosen as a plausible midpoint conversion for users who already
  clicked through
- **cart -> purchase**: target ~30-40% among these already-engaged exposures

#### Long-horizon outcome (only for purchases)

```
irritation_prob = irritation_risk * (0.6 if skin_type == "sensitive" else 0.15)
if irritation triggers (Bernoulli(irritation_prob)):
    long_horizon_signal ~ Uniform(0.0, 0.35)      # bad outcome
else:
    long_horizon_signal = clip(sigmoid(affinity) + N(0, 0.05), 0, 1)  # satisfaction tracks the same affinity that drove the purchase
```

`long_horizon_observed_date` = purchase timestamp + Uniform-integer(30, 42) days.

#### Timestamps

Exposure timestamps are sampled uniformly between each user's `signup_date`
and `TODAY - 42 days` (2026-05-25), guaranteeing every purchase's 30-42-day
follow-up date falls within the dataset's snapshot window — no outcome dated
in the future relative to "today" (2026-07-06). Within a funnel, later stages
get a small additional time offset (minutes for click/cart, up to ~2 days for
purchase) so within-funnel ordering is realistic.

`days_since_last_purchase_at_time` is computed by sorting each user's rows
chronologically and tracking the most recent purchase timestamp seen so far,
excluding the current row's own purchase (a purchase's own gap is measured
against the *previous* purchase, not itself).
